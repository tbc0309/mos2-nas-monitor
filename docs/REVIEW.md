# 1.0.0 代码整理与验证

- 主循环负责调度，应用状态只由一个编译单元持有；配置、绘图、协议采样、管理接口、路由注册、触摸处理分别维护。
- 配置使用 schema 1 JSON，去掉逐行旧格式及动画开关等废弃字段。默认小时白、分钟橙；大时钟仍使用原图数字。
- 保存配置先写临时文件，检查 JSON 容量和实际写入字节，再替换正式文件；失败时管理接口报错并回滚内存配置。
- SNMP 响应检查包边界、BER 类型、request-id 和返回 OID，拒绝截断或额外尾部数据。静态元数据和实时数据采用不同刷新周期。
- CPU 取累计计数器差值；内存排除空闲、buffers 和 cache；初次采样、缺失读数与重启不展示伪造的百分比。
- 触摸整组解析，五击管理、六击配网、八击重置请求，随后独立三击确认。闹钟控制优先。
- 相册七张，每张 240×240 baseline JPEG、48 KB；失败上传不替换原照片。出厂重置清除全部文件。
- 移除未引用的辅助函数、变量及废弃天气绘图分支；统一维护代码排版，并注明内存分块、采样与文件写入的原因。

验证入口：`python tools/check.py`（先执行 `pio run` 下载构建依赖）。包含触摸、闹钟、CPU/内存、字体、SNMP BER、天气解析，以及隔离的模拟器 HTTP 回归：多盘/卷分页、管理与配网、确认重置、相册上限、上传失败、双语、闹钟图标开关与秒数开关。

固件已完成 ESP8266 编译和本机模拟器画面检查。已在 COM7 实体 MOS2 完整擦除并刷入，写入校验通过，串口确认启动完成、文件系统正常、Wi-Fi 配置为空且无异常重启。NAS 连通性由用户重新配网后验证；LCD 观感仍需观察。首次从旧项目升级需要重新配网，不自动迁移旧配置。

首次全擦除启动只在整个文件系统分区确认为空白时初始化 LittleFS；非空分区挂载失败保持数据不变。主机测试覆盖空分区、末尾非空、读取失败和地址边界。

## NAS 翻页性能复查

- 条带外的文字提前跳过翻译和字宽查找；温度圈像素按行排序并二分定位，避免每条带扫描整圈。
- 硬盘与卷只处理当前条带覆盖的行；每页只用相关数据判断是否重绘，并补上 CPU/内存页的总量与可用量更新条件。
- 缺失的型号、卷大小和分配单位不按成功元数据缓存五分钟，下一轮继续请求。
- 删除未引用的旧天气图标与七段数码绘图；启动读取配置只在内存中规范化，避免每次开机重复写 Flash。
- `/api/diagnostics` 增加 `renderMicros`、`renderMaxMicros`，记录实际绘图耗时。
- 新增中英文六页、15px/5px 条带与完整绘图逐像素一致性测试；编译和原有回归测试一并运行。

COM7 实测：相同 HTTP 翻页测试，总览响应由约 365–371ms 降到 219–236ms（含局域网和 HTTP 开销）；六页平均响应由约 262ms 降到 204ms。最后一轮六页绘图约 99–154ms，缓冲区失败次数为零，SNMP 请求与响应数量一致、无超时；数据、网络负载和盘位数量会影响耗时。触摸仍保留 350ms 多击确认窗口，避免一组点击产生中间翻页或误触其他操作。此次按常规升级刷入并保留配置和照片，NAS 网络及多盘/卷数据读取正常。LCD 观感需用户继续观察；字体候选实验单独留在本地，不作为发布版实屏清晰度结论。
