# SNMP 采集与系统适配

采集器负责网络请求，快照负责保存有效结果，绘制只读快照。页面与后台操作不直接读取 OID。一次请求只占一个在途槽位，全局发送间隔为 500 ms，超时为 4 秒，持续失败按调度器退避。

## 模块入口

| 文件 | 责任 |
| --- | --- |
| `include/snmp/oid_catalog.h` | 有含义的 OID 常量 |
| `include/snmp/device_profile.h` | 系统分类与证据等级 |
| `include/snmp/adapter_policy.h` | 已确认系统可启用的专用能力 |
| `include/snmp/capability_plan.h` | 独立能力状态及备用路径 |
| `include/snmp/storage_policy.h` | 存储候选与标准类型筛选 |
| `include/snmp/temperature_policy.h` | 传感器名称分类、CPU 来源优先级与发现上限 |
| `src/app/telemetry/collector_state.h` | 六个采集器的单一状态所有者 |
| `src/app/telemetry/metric_queries.h` | 查询构造、响应校验、能力发现 |
| `src/app/telemetry/snapshots.h` | 原子指标提交、有效期、诊断 |
| `src/app/telemetry/scheduler.h` | 启动优先级、轮转、重试、暂停恢复 |
| `include/storage_collector.h` | 独立磁盘与卷表采集 |
| `include/network_interfaces.h` | 独立接口发现 |

## 分类与能力

首先读取标准 `sysDescr`、`sysObjectID`；无法从描述安全提取 ASCII 主机名时才查询 `sysName`。用户自定义名称和主机名不能作为系统证据。企业 OID 按完整子树边界匹配，避免将 `65740` 误识别为 `6574`。采集规则不按设备 IP 分支，私有实机配置不进入源码。

企业 OID 或成功的厂商模型响应优先于描述文本。对未能区分的 Linux Net-SNMP，可进行一次有界的群晖型号验证；明确不支持后在该目标生命周期内不再重复探测。群晖确认后启用其温度和磁盘表；只有描述文本匹配时仍使用通用路径，防止描述中含自定义主机名导致误启用。Linux、Ubuntu、OpenWrt、飞牛、威联通、铁威马及未知设备保留独立的通用能力发现，不把系统识别成功等同于所有指标可用。

| 指标 | 首选与备用路径 |
| --- | --- |
| CPU | UCD 原始计数器差值；不支持时走 HOST-RESOURCES 处理器表平均值，最多 32 行 |
| 内存 | `memSysAvail`；不支持时空闲加缓冲及缓存；再不支持时发现标准 RAM 行，最多 64 行 |
| 网络 | `ifHCInOctets` / `ifHCOutOctets`；不支持时使用 32 位计数器并检查回绕或重置 |
| 温度 | 确认群晖后使用群晖 OID；其它按 LM-SENSORS 名称和数值发现传感器；无可用项时尝试用户明确配置的 CPU 温度扩展；都不提供则不可用 |
| 运行时间 | `hrSystemUptime`；本地递增，不替换成 SNMP 服务运行时间 |
| 容量 | `hrStorageTable` 中固定磁盘、可移动磁盘、闪存类型；排除伪文件系统和容器内部路径 |

数值类型、符号、范围、OID 子树均需校验。仅解码出的 `noSuchObject`、`noSuchInstance`、`endOfMibView` 或合法表结束触发能力降级。超时、认证失败、报文损坏不能证明“不支持”，保留已有路径并退避。成功发现的能力按目标和认证身份保留；切换设备或凭据时清除，颜色、语言和翻页不清除。

网络首次计数仅建立基线，第二次才能计算速率。计数器重置不产生巨大伪速率。处理器表表示代理提供的处理器负载，其统计窗口可能与原始差值不同。USB 容量可通过标准卷表出现，但仅凭挂载目录不能证明 USB 连接；通用 SNMP 也不能保证提供 SMART 健康和磁盘温度。

接口发现接受以太网、PPP、Wi-Fi、链路聚合和桥接，默认排除回环和隧道；显式填写索引不受自动发现类型筛选限制。接口类型核对依据是 [IANA ifType 注册表](https://www.iana.org/assignments/ianaiftype-mib/ianaiftype-mib)。

## 温度发现与缓存

LM-SENSORS 行号由代理分配，第一行不一定是 CPU。[Net-SNMP 的实际示例](https://www.net-snmp.org/wiki/index.php/Net-SNMP_and_lm-sensors_on_Ubuntu_10.04)包含 CPU 核心、普通温度项和异常的无符号负值。首次发现最多检查 16 行，核对名称并拒绝越界数值：CPU / Package / Tdie / Tctl 优先，其次核心、系统/主板及未命名的通用温度。明确的硬盘、SSD、NVMe 传感器不作为设备温度来源。遇到明确的 CPU 来源即结束发现。

完成发现后缓存选中的 OID，正常刷新只做一次 GET；索引删除后重新有界发现。超时保持原有能力，不误判为不支持。缓存随目标或认证配置重置，不写入 Flash，也不因翻页反复扫描。明确 CPU 来源之外的值仍叫“设备温度”，不将未知传感器宣称为 CPU 温度。此策略依赖代理导出的标签，无法替代理辨认错误或缺失的标签。

## 查询周期

| 项目 | 常规周期 |
| --- | --- |
| 网络 | 配置的 3–60 秒，默认 5 秒；建基线后尽快再取一次 |
| CPU、内存 | 配置周期与 15 秒的较大值 |
| 设备温度 | 15 秒 |
| 身份 | 1 小时 |
| 运行时间 | 2 小时同步，其余时间本地计时 |
| 网络接口 | 5 分钟 |
| 硬盘温度 | 5 分钟 |
| 硬盘健康 | 1 小时 |
| 存储卷容量、磁盘与卷重新发现 | 2 小时 |

首轮根据当前页面优先采集，常规指标已有一次有效值或有界等待到期后，再释放表采集。非当前功能连续闲置 5 分钟可暂停，重新进入时恢复。缓存有效期与请求周期分别定义于 `include/sampling_policy.h`；失败不把单项失败扩大为整页清空。

标准身份字段先读取，企业 OID 提供可靠证据后立即应用对应规则，不等待可选型号探测。对于尚未证实厂商的 Linux 设备，可选的群晖型号探测等待 CPU/内存完成首轮有效显示，最多推迟 10 秒；已由企业 OID 确认的群晖、设备状态页面不推迟所需身份查询。CPU 原始计数器首轮只是基线，不能算作已有有效显示。通用 OID 仍可能因代理视图或模块配置不可用，不能把“标准”视为必然成功。

传输层保持一次在途、500 ms 发送间距、4秒响应超时和每 OID 一次重试；保留对较慢代理的等待，避免把慢响应误判为缺字段。显式“不支持”是正常代理响应，会结束传输故障连续计数，但仍触发对应指标的备用路径。UDP 绑定或发送失败释放队列并报告给采集器，按失败周期退避。切换目标先取消旧请求，再清除旧目标的全局失败冷却；模拟器还会取消排队的旧目标请求，迟到的旧超时不会让新目标进入冷却。

| 异常或等待 | 处理 |
| --- | --- |
| 单个 OID 超时 | 4 秒后释放在途请求，等待至少 500 ms 后重试一次 |
| 指标连续失败 | 按自身周期与 15 秒的较大值开始退避，倍增至最多 120 秒 |
| 连续三个传输超时 | 所有采集器共用 60 秒冷却；合法响应清除连续故障计数 |
| 核心指标尚未齐全 | 磁盘、卷首轮等有效值；最多等待 120 秒，直接进入磁盘/卷页时优先开始 |
| 设备或凭据切换 | 取消旧队列、清除旧能力及基线，重新发现；不继承旧目标冷却 |

首值耗时需结合串口里的 HTTP、绘图和采样时间分析，不能只看 SNMP 单次响应。ESP8266 的同步管理页处理仍会占用主循环；测试期间反复重新登录或同时操作浏览器，会改变首次采样的墙钟时间。

## 添加系统或指标

1. 根据官方 MIB 与实机响应，在 `oid_catalog.h` 添加具名 OID。
2. 在 `device_profile.h` 添加可靠的企业子树或描述证据，补前缀边界与误识别测试；不要用用户名称匹配。
3. 在 `adapter_policy.h` 显式开启已经验证的能力。未经测试的厂商保留通用能力。
4. 为新指标定义采集周期、有效期、校验、失败退避与备用路径；在查询层处理响应，在快照层完整提交。禁止显示函数发请求。
5. 对齐 `simulator/snmp_profiles.py`，加入响应缺失、超时、错误类型、计数重置和切换目标测试，再实机验证。

## 官方依据

- [HOST-RESOURCES-MIB，RFC 2790](https://www.rfc-editor.org/rfc/rfc2790)：运行时间、处理器、存储类型与容量单位。
- [Net-SNMP UCD-SNMP-MIB](https://www.net-snmp.org/docs/mibs/ucdavis.html)：内存和原始 CPU 计数；部分字段依赖操作系统实现。
- [群晖 MIB 开发文档](https://global.download.synology.com/download/Document/Software/DeveloperGuide/Firmware/DSM/All/enu/Synology_DiskStation_MIB_Guide.pdf)：群晖企业指标。
- [QTS 5.2 MIB 下载说明](https://docs.qnap.com/operating-system/qts/5.2.x/en-us/downloading-the-snmp-mib-AAB5A006.html)：新企业编号。当前仅识别厂商，未声明已验证其专用健康指标。
