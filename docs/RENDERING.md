# LCD 绘制与局部刷新

屏幕为 240×240、RGB565。完整帧需要 115200 字节，超过 ESP8266 的总 RAM，因此使用条带合成后覆盖屏幕，不能依赖整帧双缓冲。

## 更新规则

- 切页、背景/卡片色、显示语言、设备、切换提示的显示与结束：整页绘制。
- 同一监控页的数据变化：`include/dirty_bands.h` 对每个字段覆盖的区域建立指纹；只绘制变化区域相交的条带。无变化时不绘制、不发送 LCD 数据。
- 固定 24 个十行区域的指纹，不复制完整 State，也不保留字段 String。旧文字及背景在小缓冲区里一起合成，旧数字变短也不会留下笔画。
- 完整绘制结束才提交指纹。触摸打断、分配失败均不提交，后续重画保持可恢复。
- 时钟秒数和天气轮播文字也通过局部条带合成。天气文案没有改变时不再按秒清屏重写。
- 仍保留 7000 字节 Wi-Fi/TCP 余量；内存不足保留屏幕现有内容，并在后续循环重试，不直接清屏。

## 二次开发

新增或移动可变 UI 内容时，同时更新 `DirtyBands::monitor()` 的依赖字段与纵向范围。范围必须覆盖最大字高、图形、旧内容及背景。页间或主题变化依靠上层上下文失效，不能仅依赖数据变化。

本地脏区域回归 对中英文六页各字段变化验证：保留旧图的未更新区域、合入新图的更新区域后，像素必须与完整新图完全一致。本地分块绘图回归 验证不同条带高度、末条带以及中文裁剪与滚动。发布前在本地执行这些检查。

## 诊断

- `renderMicros`：最后一次监控/完整条带绘制的耗时。
- `renderRows`：该次传输的行数，整页为 240，局部刷新通常更少。
- `partialDraws`：监控页面局部更新完成次数。
- `bufferedDraws`：条带绘制完成次数。

上述计数不包含时钟秒数、城市滚动及 JPEG 动画的独立绘制。耗时不是手指点击到整页完成时间；单击多击识别仍有约 350 毫秒等待。软件像素校验不能替代用户对实体屏幕观感的确认。
